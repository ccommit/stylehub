# 토스페이먼츠 결제 테스트 가이드

Postman과 토스 샌드박스를 사용하여 결제 전체 흐름을 테스트하는 방법을 설명한다.

---

## 사전 준비

### 1. 토스 개발자센터 키 확인

1. https://developers.tosspayments.com 접속 → 로그인
2. 왼쪽 메뉴 **내 개발정보** 클릭
3. 아래 두 키를 메모:
   - **클라이언트 키** (test_ck_xxx): 샌드박스에서 결제창 띄울 때 사용
   - **시크릿 키** (test_sk_xxx): 서버에서 승인 API 호출할 때 사용

### 2. application.properties 확인

```properties
toss.payments.secret-key=test_sk_0RnYX2w532DgPq7bWZq1rNeyqApQ
toss.payments.confirm-url=https://api.tosspayments.com/v1/payments/confirm
```

시크릿 키가 개발자센터의 테스트 시크릿 키와 동일한지 확인한다.

### 3. 서버 실행

- MySQL 실행 중인지 확인
- Redis 실행 중인지 확인 (`redis-cli ping` → PONG)
- IntelliJ에서 StylehubApplication 실행

### 4. Postman 설정

- 새 Collection 생성: "StyleHub 결제 테스트"
- 모든 요청에 공통 Header 추가:
  - Content-Type: application/json

---

## 테스트 1: 결제 승인 (정상 흐름)

### Step 1: 로그인

**Postman에서:**

```
POST http://localhost:8080/api/v1/users/login
```

Body (raw → JSON):
```json
{
  "email": "test@test.com",
  "password": "password123"
}
```

Send 클릭.

**확인할 것:**
- 응답 200 OK
- Postman 하단 **Cookies** 탭 클릭 → `JSESSIONID` 값이 있는지 확인
- Postman은 쿠키를 자동으로 저장하므로 이후 요청에 자동 포함됨

> 만약 쿠키가 자동 포함 안 되면: Headers에 Cookie: JSESSIONID={값} 직접 추가

---

### Step 2: 주문 생성

**Postman에서:**

```
POST http://localhost:8080/api/v1/orders
```

Body (raw → JSON):
```json
{
  "addressId": 1,
  "items": [
    {
      "productOptionId": 1,
      "quantity": 1
    }
  ]
}
```

Send 클릭.

**응답 예시:**
```json
{
  "orderId": 1,
  "pgOrderId": "ORD-20260402-a1b2c3d4",
  "orderStatus": "PENDING",
  "items": [...],
  "totalAmount": 129000,
  "finalAmount": 129000,
  "createdAt": "2026-04-02T10:00:00"
}
```

**반드시 메모할 것:**
- `pgOrderId` (예: ORD-20260402-a1b2c3d4)
- `finalAmount` (예: 129000)

이 두 값을 다음 단계에서 사용한다.

---

### Step 3: 토스 샌드박스에서 결제 인증

**브라우저에서:**

아래 URL을 주소창에 붙여넣는다. `{}`  안의 값을 본인 것으로 교체:

```
https://developers.tosspayments.com/sandbox/widget?clientKey={클라이언트키}&customerKey=customer_1&orderId={pgOrderId}&orderName=테스트주문&amount={finalAmount}&successUrl=http://localhost:8080/api/v1/payments/success&failUrl=http://localhost:8080/api/v1/payments/fail
```

**실제 예시:**
```
https://developers.tosspayments.com/sandbox/widget?clientKey=test_ck_QbgMGZzorzqRAEpGbAqkVl5E1em4&customerKey=customer_1&orderId=ORD-20260402-a1b2c3d4&orderName=테스트주문&amount=129000&successUrl=http://localhost:8080/api/v1/payments/success&failUrl=http://localhost:8080/api/v1/payments/fail
```

**브라우저 화면에서:**
1. 결제 위젯이 표시된다
2. 결제 수단 선택 (카드, 간편결제 등)
3. **결제하기** 버튼 클릭
4. 테스트 환경이므로 실제 결제는 안 됨 — 인증만 진행
5. 인증 완료 후 자동으로 successUrl로 리다이렉트

**리다이렉트 후 브라우저에 표시되는 것:**

성공하면 브라우저에 JSON 응답이 표시된다:
```json
{
  "paymentId": 1,
  "paymentKey": "tgen_20260402xxxxxx",
  "orderId": "ORD-20260402-a1b2c3d4",
  "status": "DONE",
  "totalAmount": 129000,
  "approvedAmount": 129000,
  "approvedAt": "2026-04-02T10:05:00"
}
```

실패하면 에러 JSON이 표시된다 — IntelliJ 콘솔 로그를 확인한다.

**`paymentId`를 메모한다** — 취소 테스트에서 사용.

---

### Step 4: 주문 상태 확인

**Postman에서:**

```
GET http://localhost:8080/api/v1/orders/{orderId}
```

예: `GET http://localhost:8080/api/v1/orders/1`

**확인할 것:**
- `orderStatus`가 `"PAID"`로 변경되었는지

---

## 테스트 2: 전액 취소

Step 1~4의 결제 승인이 완료된 상태에서 진행한다.

### Step 5: 전액 취소 요청

**Postman에서:**

```
POST http://localhost:8080/api/v1/payments/{paymentId}/cancel
```

예: `POST http://localhost:8080/api/v1/payments/1/cancel`

Body (raw → JSON):
```json
{
  "cancelReason": "고객 요청에 의한 전액 취소"
}
```

> cancelAmount를 넣지 않으면 전액 취소

Send 클릭.

**예상 응답:**
```json
{
  "paymentId": 1,
  "paymentKey": "tgen_20260402xxxxxx",
  "orderId": "ORD-20260402-a1b2c3d4",
  "status": "CANCELED",
  "totalAmount": 129000,
  "approvedAmount": 129000,
  "approvedAt": "2026-04-02T10:05:00"
}
```

### Step 6: 취소 후 주문 상태 확인

**Postman에서:**

```
GET http://localhost:8080/api/v1/orders/1
```

- `orderStatus`가 `"CANCELLED"`로 변경되었는지 확인

---

## 테스트 3: 부분 취소

**새로운 주문 + 결제 승인을 먼저 진행해야 한다** (Step 1~4 반복).

### Step 7: 부분 취소 요청

**Postman에서:**

```
POST http://localhost:8080/api/v1/payments/{paymentId}/cancel
```

Body (raw → JSON):
```json
{
  "cancelReason": "일부 상품 반품",
  "cancelAmount": 30000
}
```

> cancelAmount에 취소할 금액을 넣으면 부분 취소

**예상 응답:**
```json
{
  "paymentId": 2,
  "status": "PARTIAL_CANCELED",
  "totalAmount": 129000,
  "approvedAmount": 129000
}
```

### Step 8: 추가 부분 취소

같은 paymentId로 한 번 더:

```json
{
  "cancelReason": "추가 반품",
  "cancelAmount": 50000
}
```

잔액이 줄어드는 것을 확인한다.

### Step 9: 잔액 초과 취소 (에러 확인)

```json
{
  "cancelReason": "잔액 초과 테스트",
  "cancelAmount": 999999
}
```

**예상 에러:**
```json
{
  "status": 400,
  "code": "PM006",
  "message": "취소 금액이 잔액을 초과합니다"
}
```

---

## 테스트 4: 결제 실패

### Step 10: 주문 생성 (Step 1~2 반복)

새 주문을 생성하고 pgOrderId, finalAmount를 메모한다.

### Step 11: 토스 샌드박스에서 결제 취소

Step 3과 동일하게 샌드박스 URL을 브라우저에 입력하되, 결제창에서 **결제하기 대신 취소/닫기**를 누른다.

또는 **Postman에서 직접 fail URL 호출:**

```
GET http://localhost:8080/api/v1/payments/fail?code=PAY_PROCESS_CANCELED&message=사용자가 결제를 취소했습니다&orderId={pgOrderId}
```

**확인할 것:**
- 주문 상태가 `CANCELLED`로 변경
- 재고가 복구되었는지 (상품 상세 조회로 확인)

---

## 테스트 5: 위변조 검증

### Step 12: 금액 조작 테스트

Step 1~2로 주문을 생성한 후, Postman에서 직접 success URL을 호출하되 **금액을 다르게** 넣는다:

```
GET http://localhost:8080/api/v1/payments/success?paymentKey=fake_key&orderId={pgOrderId}&amount=1000
```

DB에 저장된 금액(예: 129000)과 다른 금액(1000)을 보낸다.

**예상 에러:**
```json
{
  "status": 400,
  "code": "PM002",
  "message": "결제 금액이 일치하지 않습니다"
}
```

이 에러가 반환되면 위변조 검증이 정상 동작하는 것이다.

---

## 테스트 6: 이미 처리된 결제 중복 요청

### Step 13: 이미 취소된 결제를 다시 취소

테스트 2에서 전액 취소한 paymentId로 다시 취소 요청:

```
POST http://localhost:8080/api/v1/payments/1/cancel
```

```json
{
  "cancelReason": "중복 취소 테스트"
}
```

**예상 에러:**
```json
{
  "status": 409,
  "code": "PM003",
  "message": "이미 처리된 결제입니다"
}
```

## 에러 발생 시 확인 순서

### 1. IntelliJ 콘솔 로그 확인

토스 API 에러는 콘솔에 상세 메시지가 찍힌다:
```
토스 결제 승인 실패: orderId=ORD-xxx, status=401, body={"code":"UNAUTHORIZED_KEY","message":"..."}
```

### 2. 흔한 에러와 해결법

| 에러 | 원인 | 해결 |
|---|---|---|
| `UNAUTHORIZED_KEY` | 시크릿 키가 틀림 | application.properties의 시크릿 키 확인 |
| `NOT_FOUND_PAYMENT_SESSION` | 결제 세션 만료 (10분) | Step 3을 10분 이내에 완료 |
| `INVALID_REQUEST` | orderId 또는 amount 불일치 | pgOrderId와 finalAmount가 정확한지 확인 |
| `PM002` | 위변조 검증 실패 | 샌드박스에 입력한 amount와 주문 생성 시 finalAmount가 같은지 확인 |
| `PM001` | Payment를 찾을 수 없음 | pgOrderId가 정확한지 확인 (대소문자, 하이픈 포함) |
| 서버 시작 실패 (Schema validation) | DB에 컬럼 없음 | ddl-auto를 update로 잠시 변경하거나 ALTER TABLE 실행 |

### 3. 토스 개발자센터에서 결제 내역 확인

1. https://developers.tosspayments.com 접속
2. **결제내역** 메뉴에서 테스트 결제 건을 확인할 수 있다
3. 승인/취소 상태, 금액, 시간 등을 확인

---

## 전체 테스트 체크리스트

```
□ Step 1:  로그인 → JSESSIONID 확보
□ Step 2:  주문 생성 → pgOrderId, finalAmount 메모
□ Step 3:  토스 샌드박스 결제 인증 → 브라우저에 성공 JSON 표시
□ Step 4:  주문 상태 확인 → PAID
□ Step 5:  전액 취소 → CANCELED
□ Step 6:  주문 상태 확인 → CANCELLED
□ Step 7:  (새 주문+결제) 부분 취소 → PARTIAL_CANCELED
□ Step 8:  추가 부분 취소 → 잔액 감소 확인
□ Step 9:  잔액 초과 취소 → PM006 에러
□ Step 10: (새 주문) 결제 실패 테스트
□ Step 11: 결제 취소/닫기 → CANCELLED + 재고 복구
□ Step 12: 위변조 검증 → PM002 에러
□ Step 13: 중복 취소 → PM003 에러
```
