# 토스페이먼츠 결제 취소/부분 취소/환불 테스트 방법

## 사전 조건

결제 취소를 테스트하려면 **승인된 결제 건**이 있어야 한다.
먼저 결제 승인까지 완료한 후 취소 테스트를 진행한다.

---

## 1단계: 결제 승인 완료하기

### 1-1. 서버 실행

IntelliJ에서 StylehubApplication 실행.
MySQL, Redis가 실행 중이어야 한다.

### 1-2. 로그인 (Postman)

```
POST http://localhost:8080/api/v1/users/login
Content-Type: application/json

{
  "email": "test@test.com",
  "password": "password123"
}
```

응답 헤더의 Set-Cookie에서 JSESSIONID 값을 복사한다.

### 1-3. 주문 생성 (Postman)

```
POST http://localhost:8080/api/v1/orders
Content-Type: application/json
Cookie: JSESSIONID={1-2에서 받은 값}

{
  "addressId": 1,
  "items": [
    {
      "productOptionId": 1,
      "quantity": 1
    }
  ]
}
```

응답에서 메모:
- pgOrderId (예: ORD-20260401-a1b2c3d4)
- finalAmount (예: 129000)

### 1-4. 토스 샌드박스에서 결제 인증 (브라우저)

브라우저 주소창에 아래 URL을 입력한다.
{} 안의 값을 본인 것으로 교체:

```
https://developers.tosspayments.com/sandbox/widget?clientKey={토스 클라이언트 키}&customerKey=customer_1&orderId={pgOrderId}&orderName=테스트주문&amount={finalAmount}&successUrl=http://localhost:8080/api/v1/payments/success&failUrl=http://localhost:8080/api/v1/payments/fail
```

결제 수단 선택 → 인증 완료 → 브라우저에 성공 응답 JSON이 표시되면 결제 승인 완료.

### 1-5. 결제 승인 확인 (Postman)

```
GET http://localhost:8080/api/v1/orders/{orderId}
Cookie: JSESSIONID={세션ID}
```

orderStatus가 PAID인지 확인한다.

---

## 2단계: 전액 취소 테스트

결제 승인이 완료된 상태에서 진행한다.

### 요청 (Postman)

```
POST http://localhost:8080/api/v1/payments/{paymentId}/cancel
Content-Type: application/json
Cookie: JSESSIONID={세션ID}

{
  "cancelReason": "고객 요청에 의한 전액 취소"
}
```

- paymentId: 결제 승인 응답에서 받은 paymentId
- cancelAmount를 넣지 않으면 전액 취소

### 예상 응답

```json
{
  "paymentId": 1,
  "paymentKey": "tgen_xxx",
  "orderId": "ORD-20260401-a1b2c3d4",
  "status": "CANCELED",
  "totalAmount": 129000,
  "approvedAmount": 129000,
  "approvedAt": "2026-04-01T22:10:00"
}
```

### 확인

```
GET http://localhost:8080/api/v1/orders/{orderId}
Cookie: JSESSIONID={세션ID}
```

- orderStatus: CANCELLED
- 재고가 복구되었는지 확인 (상품 상세 조회로 재고 수량 확인)

---

## 3단계: 부분 취소 테스트

부분 취소를 테스트하려면 새로운 주문 + 결제 승인을 다시 진행해야 한다.
(2단계에서 전액 취소한 건은 더 이상 취소할 수 없음)

### 3-1. 새 주문 생성 + 결제 승인

1단계를 다시 진행하여 결제 승인 완료 상태를 만든다.

### 3-2. 부분 취소 요청 (Postman)

```
POST http://localhost:8080/api/v1/payments/{paymentId}/cancel
Content-Type: application/json
Cookie: JSESSIONID={세션ID}

{
  "cancelReason": "일부 상품 반품",
  "cancelAmount": 30000
}
```

- cancelAmount: 취소할 금액 (전체 금액보다 작아야 함)

### 예상 응답

```json
{
  "paymentId": 2,
  "paymentKey": "tgen_xxx",
  "orderId": "ORD-20260401-b2c3d4e5",
  "status": "PARTIAL_CANCELED",
  "totalAmount": 129000,
  "approvedAmount": 129000,
  "approvedAt": "2026-04-01T22:20:00"
}
```

status가 PARTIAL_CANCELED로 변경된다.

### 3-3. 추가 부분 취소

같은 결제 건에 대해 한 번 더 부분 취소 가능:

```
POST http://localhost:8080/api/v1/payments/{paymentId}/cancel
Content-Type: application/json
Cookie: JSESSIONID={세션ID}

{
  "cancelReason": "추가 반품",
  "cancelAmount": 50000
}
```

### 3-4. 잔액 초과 취소 (에러 테스트)

남은 잔액보다 큰 금액으로 취소 요청:

```
POST http://localhost:8080/api/v1/payments/{paymentId}/cancel
Content-Type: application/json
Cookie: JSESSIONID={세션ID}

{
  "cancelReason": "잔액 초과 테스트",
  "cancelAmount": 999999
}
```

예상 에러 응답:
```json
{
  "status": 400,
  "code": "PM006",
  "message": "취소 금액이 잔액을 초과합니다"
}
```

## 4단계: 환불 테스트

환불은 전액 취소/부분 취소와 같은 API를 사용한다.
사유만 다르게 입력하면 된다.

```
POST http://localhost:8080/api/v1/payments/{paymentId}/cancel
Content-Type: application/json
Cookie: JSESSIONID={세션ID}

{
  "cancelReason": "배송 완료 후 반품에 의한 환불",
  "cancelAmount": 129000
}
```

---

## 에러 케이스 테스트

### 이미 취소된 결제를 다시 취소

전액 취소한 결제 건에 다시 취소 요청:

```json
{
  "status": 409,
  "code": "PM003",
  "message": "이미 처리된 결제입니다"
}
```

### 취소 사유 누락

```
POST http://localhost:8080/api/v1/payments/{paymentId}/cancel
Content-Type: application/json

{
  "cancelAmount": 30000
}
```

cancelReason이 없으면 유효성 검증 실패.

### 존재하지 않는 paymentId

```
POST http://localhost:8080/api/v1/payments/99999/cancel
```

```json
{
  "status": 404,
  "code": "PM001",
  "message": "존재하지 않는 결제입니다"
}
```

## 전체 테스트 순서 요약

```
1. 로그인 → JSESSIONID 확보
2. 주문 생성 → pgOrderId, finalAmount 메모
3. 토스 샌드박스 결제 인증 → 브라우저에서 결제 완료
4. 주문 상태 확인 → PAID
5. 전액 취소 → status: CANCELED, orderStatus: CANCELLED
6. (새 주문 + 결제) → 부분 취소 → status: PARTIAL_CANCELED
7. 추가 부분 취소 → 잔액 감소 확인
8. 잔액 초과 취소 → PM006 에러 확인
9. 이미 취소된 건 재취소 → PM003 에러 확인
```
