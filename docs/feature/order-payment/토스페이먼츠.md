# 토스페이먼츠 결제 연동 절차

## 전체 흐름
```
프론트(샌드박스) → 토스 결제창 → 사용자 인증 → successUrl로 리다이렉트 → 우리 서버에서 금액 검증 → 토스 승인 API 호출 → 결제 완료
```

---

## 1단계: 결제 준비 (주문 생성 시)

주문 생성(placeOrder) 시 아래 데이터를 서버에 저장한다.

- `pgOrderId`: 토스에 넘길 주문번호. 우리 DB의 auto increment PK를 그대로 노출하면 보안 위험이 있으므로 UUID 기반으로 생성한다. (현재 Order.generatePgOrderId()에서 "ORD-날짜-UUID8자리" 형식으로 생성 중)
- `requestedAmount`: 결제 요청 금액. 승인 전에 서버에 저장해둬야 나중에 위변조 검증이 가능하다.
- Payment 엔티티를 READY 상태로 생성하여 DB에 저장한다.

---

## 2단계: 토스 결제창 진입 (프론트 or 샌드박스)

프론트가 없는 테스트 환경이므로 토스 샌드박스(https://developers.tosspayments.com/sandbox)를 사용한다.

샌드박스에 아래 값을 입력한다:
- `orderId`: 1단계에서 생성한 pgOrderId
- `amount`: 결제 금액
- `successUrl`: http://localhost:8080/api/v1/payments/success
- `failUrl`: http://localhost:8080/api/v1/payments/fail

사용자가 결제 수단을 선택하고 인증을 완료한다.

---

## 3단계: 인증 완료 후 리다이렉트 (토스 → 우리 서버)

인증이 완료되면 토스가 우리 서버의 successUrl로 리다이렉트한다.

```
GET /api/v1/payments/success?paymentKey={결제고유키}&orderId={pgOrderId}&amount={결제금액}
```

- paymentKey: 토스가 발급한 결제 고유키. 승인 API 호출 시 필요.
- orderId: 우리가 1단계에서 생성한 pgOrderId
- amount: 결제 금액

이 시점에서는 아직 돈이 빠져나간 상태가 아니다. 인증만 완료된 상태.

---

## 4단계: 금액 위변조 검증 (우리 서버)

리다이렉트로 받은 amount와 1단계에서 DB에 저장한 requestedAmount를 비교한다.

- 일치하면: 5단계 승인 API 호출 진행
- 불일치하면: 결제 거부 (클라이언트가 금액을 조작한 위변조 공격)

토스 공식문서에서도 서버에서 반드시 검증하라고 명시되어 있다.

---

## 5단계: 토스 승인 API 호출 (우리 서버 → 토스)

```
POST https://api.tosspayments.com/v1/payments/confirm
```

헤더:
- Authorization: Basic {Base64(시크릿키 + ":")}
- Content-Type: application/json

바디:
```json
{
  "paymentKey": "3단계에서 받은 값",
  "orderId": "pgOrderId",
  "amount": 결제금액
}
```

시크릿키는 토스 개발자센터에서 발급받는다. 절대 클라이언트에 노출하면 안 된다.

---

## 6단계: 결과 처리 (우리 서버)

토스에서 200 OK를 받으면 결제 승인 완료.

- Payment 상태: READY → DONE
- Order 상태: PENDING → PAID
- 타임아웃 타이머 제거 (Redis ZSET에서 해당 주문 제거)

토스에서 에러 응답을 받으면 결제 실패.
- Payment 상태: ABORTED
- Order 상태: 유지 (PENDING) 또는 취소 처리

---

## 인증 방식

토스페이먼츠는 HTTP Basic 인증을 사용한다.

1. 시크릿키 뒤에 콜론(:)을 붙인다
2. Base64로 인코딩한다
3. Authorization 헤더에 "Basic {인코딩된값}"을 넣는다

```
시크릿키: test_gsk_docs_OaPz8L5KdmQXkzRz3y47BMw6
인코딩: Base64("test_gsk_docs_OaPz8L5KdmQXkzRz3y47BMw6:")
결과: dGVzdF9nc2tfZG9jc19PYVB6OEw1S2RtUVhrelJ6M3k0N0JNdzY6
헤더: Authorization: Basic dGVzdF9nc2tfZG9jc19PYVB6OEw1S2RtUVhrelJ6M3k0N0JNdzY6
```

---

## 테스트 환경 참고

- 테스트 키(test_sk, test_gsk)를 사용하면 실제 결제가 되지 않는다
- API 호출 제한: 테스트 환경에서 분당 100건
- 결제 세션 유효시간: 10분 (인증 후 10분 내에 승인 API를 호출해야 한다)
- 에러 시뮬레이션: 요청 헤더에 TossPayments-Test-Code를 추가하면 특정 에러를 재현할 수 있다
