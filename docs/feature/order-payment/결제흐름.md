# StyleHub 결제 흐름

## 참여자

- **사용자**: 브라우저에서 결제하는 고객
- **우리 서버**: StyleHub Spring Boot 서버 (localhost:8080)
- **토스 서버**: 토스페이먼츠 API 서버 (api.tosspayments.com)

---

## 전체 흐름

```
사용자 → 우리 서버 → 토스 서버 → 사용자 → 우리 서버 → 토스 서버 → 우리 서버
```

---

## 1단계: 주문 생성

```
사용자 → 우리 서버
POST /api/v1/orders
```

사용자가 상품을 선택하고 주문하기를 누르면, 우리 서버에 주문 생성을 요청한다.

**우리 서버가 하는 일:**
- 주문(Order) 생성 + UUID 기반 pgOrderId 발급 (예: ORD-20260403-a1b2c3d4)
- 비관적 락으로 재고 차감
- Payment를 READY 상태로 생성, requestedAmount(결제 금액) 저장
- Redis ZSET에 30분 타임아웃 타이머 등록

**이 시점의 상태:**
- Order: PENDING (결제 대기)
- Payment: READY (승인 전)
- 재고: 차감 완료
- 토스 서버: 아직 아무것도 모름

**사용자에게 반환:**
- pgOrderId, finalAmount → 이 값으로 토스 결제창에 진입

---

## 2단계: 토스 결제창 진입

```
사용자 → 토스 서버
```

사용자의 브라우저에서 토스 JS SDK가 결제위젯을 렌더링한다. 우리 서버의 test-payment.html 페이지에서 진행.

**토스 서버에 전달하는 정보:**
- clientKey: 토스 개발자센터에서 발급받은 클라이언트 키
- orderId: 우리 서버가 생성한 pgOrderId
- amount: 결제 금액
- successUrl: http://localhost:8080/api/v1/payments/success (인증 성공 시 리다이렉트할 우리 서버 URL)
- failUrl: http://localhost:8080/api/v1/payments/fail (인증 실패 시 리다이렉트할 우리 서버 URL)

**사용자가 하는 일:**
- 결제 수단 선택 (카드, 간편결제 등)
- 카드 번호 입력, 비밀번호 입력 등 인증 절차 진행

**이 시간 동안 우리 서버는 아무것도 안 한다.** DB 커넥션도 잡고 있지 않다. 트랜잭션 1은 이미 끝났기 때문이다.

---

## 3단계: 토스 인증 완료 → 우리 서버로 리다이렉트

```
토스 서버 → 사용자 브라우저 → 우리 서버
GET /api/v1/payments/success?paymentKey={키}&orderId={pgOrderId}&amount={금액}
```

사용자가 인증을 완료하면, 토스 서버가 사용자의 브라우저를 우리 서버의 successUrl로 리다이렉트시킨다.

**토스 서버가 보내는 파라미터:**
- paymentKey: 토스가 이 결제 건에 발급한 고유 키 (이후 승인/취소에 사용)
- orderId: 우리가 1단계에서 보낸 pgOrderId (그대로 돌려줌)
- amount: 결제 금액

**중요:** 이 시점에서 아직 돈이 빠져나가지 않았다. 인증만 완료된 상태이다.

**중요:** 이 리다이렉트는 사용자의 브라우저를 경유하기 때문에, amount가 조작될 수 있다.

---

## 4단계: 금액 위변조 검증

```
우리 서버 내부
```

우리 서버의 PaymentController.paymentSuccess()가 호출된다.

**우리 서버가 하는 일:**
1. pgOrderId로 1단계에서 생성한 Payment를 DB에서 조회
2. DB에 저장된 requestedAmount와 토스가 보낸 amount를 비교
3. 불일치하면 → PAYMENT_AMOUNT_MISMATCH 에러, 결제 중단

```
DB의 requestedAmount: 129000 (우리 서버가 계산한 금액, 조작 불가)
토스가 보낸 amount: 129000 (클라이언트를 경유해서 왔기 때문에 조작 가능)
→ 일치하면 통과, 불일치하면 차단
```

## 5단계: 토스 승인 API 호출

```
우리 서버 → 토스 서버
POST https://api.tosspayments.com/v1/payments/confirm
```

금액 검증을 통과하면, 우리 서버가 토스 서버에 최종 승인을 요청한다.

**우리 서버가 보내는 정보:**
- Authorization: Basic {Base64(시크릿키:)} — 시크릿키로 인증
- paymentKey: 3단계에서 토스가 보낸 결제 고유 키
- orderId: pgOrderId
- amount: 결제 금액

**이 요청이 성공하면 실제로 돈이 빠져나간다.**

**토스 서버가 200 OK를 반환하면:**
- 결제 승인 완료
- 토스 서버에 이 결제 건이 "승인됨"으로 기록됨

---

## 6단계: 우리 서버 상태 업데이트

```
우리 서버 내부
```

토스 서버에서 200 OK를 받으면, 우리 서버가 DB를 업데이트한다.

**우리 서버가 하는 일:**
- Payment 상태: READY → DONE
- Payment에 paymentKey 저장 (이후 취소 시 필요)
- Order 상태: PENDING → PAID
- Order 배송 상태: null → PREPARING (배송 준비 중)
- Redis 타임아웃 타이머 제거 (결제 완료됐으니 취소할 필요 없음)

**사용자에게 반환:**
```json
{
  "paymentId": 1,
  "paymentKey": "tgen_20260403xxxxxx",
  "orderId": "ORD-20260403-a1b2c3d4",
  "status": "DONE",
  "totalAmount": 129000,
  "approvedAmount": 129000
}
```

## 전체 흐름 다이어그램

```
[사용자]                    [우리 서버]                     [토스 서버]
   |                           |                              |
   |  1. POST /orders          |                              |
   |-------------------------->|                              |
   |  pgOrderId, finalAmount   |                              |
   |<--------------------------|                              |
   |                           |                              |
   |  2. 결제창 진입 (JS SDK)    |                              |
   |--------------------------------------------------------->|
   |                           |                              |
   |  카드 선택, 인증             |                              |
   |--------------------------------------------------------->|
   |                           |                              |
   |  3. 인증 완료 → 리다이렉트    |                              |
   |<---------------------------------------------------------|
   |  successUrl + paymentKey + orderId + amount               |
   |                           |                              |
   |  GET /payments/success    |                              |
   |-------------------------->|                              |
   |                           |  4. 위변조 검증 (DB 금액 비교)   |
   |                           |                              |
   |                           |  5. POST /v1/payments/confirm |
   |                           |----------------------------->|
   |                           |         200 OK               |
   |                           |<-----------------------------|
   |                           |                              |
   |                           |  6. Payment DONE, Order PAID  |
   |                           |     타이머 제거                |
   |                           |                              |
   |  결제 완료 응답              |                              |
   |<--------------------------|                              |
```

## 결제 실패 시

```
[사용자]                    [우리 서버]                     [토스 서버]
   |                           |                              |
   |  결제창에서 취소/실패          |                              |
   |<---------------------------------------------------------|
   |  failUrl + code + message + orderId                       |
   |                           |                              |
   |  GET /payments/fail       |                              |
   |-------------------------->|                              |
   |                           |  Payment → ABORTED            |
   |                           |  주문 취소 + 재고 복구           |
   |                           |  Redis 타이머 제거             |
```

---

## 결제 취소 시

```
[사용자/관리자]               [우리 서버]                     [토스 서버]
   |                           |                              |
   |  POST /payments/{id}/cancel|                              |
   |-------------------------->|                              |
   |                           |  CancelPolicy 검증            |
   |                           |  (배송 상태별 취소 가능 여부)     |
   |                           |                              |
   |                           |  POST /v1/payments/{key}/cancel
   |                           |----------------------------->|
   |                           |         200 OK               |
   |                           |<-----------------------------|
   |                           |                              |
   |                           |  Payment → CANCELED           |
   |                           |  Order → CANCELLED            |
   |                           |  재고 복구                     |
```

## 30분 미결제 타임아웃

```
[Redis]                     [우리 서버]
   |                           |
   |  스케줄러 1분마다 폴링        |
   |<--------------------------|
   |  만료된 주문 ID 반환         |
   |-------------------------->|
   |                           |  주문 취소 + 재고 복구
   |                           |  Payment → ABORTED
```

사용자가 2단계에서 결제를 안 하고 30분이 지나면, Redis 스케줄러가 자동으로 주문을 취소하고 재고를 복구한다.

---

## 핵심 포인트

1. **우리 서버와 토스 서버는 2번 통신한다**: 승인 요청(5단계)과 취소 요청. 나머지는 사용자 브라우저를 경유.
2. **돈이 빠져나가는 시점은 5단계**이다. 3단계(인증 완료)에서는 아직 빠져나가지 않는다.
3. **위변조 검증(4단계)이 없으면** 클라이언트가 amount를 조작하여 1000원에 상품을 살 수 있다.
4. **트랜잭션이 분리된 이유**: 2단계에서 사용자가 결제창을 고민하는 동안 DB 커넥션을 점유하면 서비스가 죽는다.
5. **paymentKey는 토스가 발급**한다. 우리가 만드는 게 아니다. 승인/취소 시 이 키로 토스 서버에 요청한다.
