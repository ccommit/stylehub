# 토스페이먼츠 결제 테스트 방법

## 방법 1: Postman + 토스 샌드박스 (실제 토스 연동 테스트)

### 사전 준비

1. 토스 개발자센터 회원가입: https://developers.tosspayments.com
2. 로그인 후 **내 개발정보** 메뉴에서 아래 키 확인
   - 클라이언트 키: `test_ck_xxx` (프론트에서 사용)
   - 시크릿 키: `test_sk_xxx` (서버에서 사용, application.properties에 설정)
3. application.properties에 시크릿 키가 설정되어 있는지 확인
   ```
   toss.payments.secret-key=test_sk_xxx
   toss.payments.confirm-url=https://api.tosspayments.com/v1/payments/confirm
   ```
4. MySQL, Redis 실행 상태 확인
5. IntelliJ에서 StylehubApplication 실행

### 테스트 순서

#### 1단계: 로그인 (Postman)

```
POST http://localhost:8080/api/v1/users/login
Content-Type: application/json

{
  "email": "test@test.com",
  "password": "password123"
}
```

- 응답 헤더의 Set-Cookie에서 JSESSIONID 값을 복사
- Postman에서 이후 요청 시 Headers에 Cookie: JSESSIONID={값} 추가

#### 2단계: 주문 생성 (Postman)

```
POST http://localhost:8080/api/v1/orders
Content-Type: application/json
Cookie: JSESSIONID={1단계에서 받은 값}

{
  "addressId": 1,
  "items": [
    {
      "productOptionId": 1,
      "quantity": 1
    }
  ]
}
```

응답 예시:
```json
{
  "orderId": 1,
  "pgOrderId": "ORD-20260401-a1b2c3d4",
  "totalAmount": 129000,
  "finalAmount": 129000
}
```

**pgOrderId와 finalAmount를 반드시 메모한다.**

#### 3단계: 토스 결제 인증 (브라우저)

브라우저에서 아래 URL을 직접 입력한다. 값은 2단계에서 받은 것으로 교체:

```
https://developers.tosspayments.com/sandbox/widget
  ?clientKey={토스 개발자센터의 클라이언트 키}
  &customerKey=customer_1
  &orderId={pgOrderId}
  &orderName=테스트주문
  &amount={finalAmount}
  &successUrl=http://localhost:8080/api/v1/payments/success
  &failUrl=http://localhost:8080/api/v1/payments/fail
```

예시:
```
https://developers.tosspayments.com/sandbox/widget?clientKey=test_ck_QbgMGZzorzqRAEpGbAqkVl5E1em4&customerKey=customer_1&orderId=ORD-20260401-a1b2c3d4&orderName=테스트주문&amount=129000&successUrl=http://localhost:8080/api/v1/payments/success&failUrl=http://localhost:8080/api/v1/payments/fail
```

결제 수단을 선택하고 인증을 완료하면 토스가 자동으로 successUrl로 리다이렉트한다.

#### 4단계: 결제 승인 (자동)

3단계에서 인증 완료 후 브라우저가 자동으로 아래 URL로 이동:

```
http://localhost:8080/api/v1/payments/success
  ?paymentKey={토스가 생성한 결제 고유키}
  &orderId={pgOrderId}
  &amount={finalAmount}
```

서버에서 자동 처리:
1. 금액 위변조 검증 (DB 금액 vs 토스 전달 금액)
2. 토스 승인 API 호출 (POST /v1/payments/confirm)
3. Payment 상태 → DONE
4. Order 상태 → PAID
5. Redis 타임아웃 타이머 제거

브라우저에 성공 응답 JSON이 표시되면 결제 완료.

#### 5단계: 결과 확인 (Postman)

```
GET http://localhost:8080/api/v1/orders/1
Cookie: JSESSIONID={세션ID}
```

orderStatus가 PAID로 변경되었는지 확인.

## 방법 2: Postman만으로 테스트 (Mock 모드)

토스 샌드박스 없이 우리 서버 로직만 검증하는 방법.
토스 승인 API 호출을 건너뛰고, 위변조 검증 + 상태 변경만 테스트한다.

### 설정

application.properties에 아래 추가:
```
toss.payments.mock-mode=true
```

TossPaymentClient에서 mock-mode가 true이면 실제 API 호출을 건너뛴다. (코드 수정 필요)

### 테스트 순서

#### 1단계: 로그인 (위와 동일)

#### 2단계: 주문 생성 (위와 동일)

pgOrderId와 finalAmount 메모.

#### 3단계: 결제 승인 직접 호출 (Postman)

```
GET http://localhost:8080/api/v1/payments/success?paymentKey=mock_key&orderId={pgOrderId}&amount={finalAmount}
```

예시:
```
GET http://localhost:8080/api/v1/payments/success?paymentKey=mock_key&orderId=ORD-20260401-a1b2c3d4&amount=129000
```

Mock 모드에서는 토스 API 호출을 건너뛰고 바로 성공 처리.

#### 4단계: 결과 확인 (위와 동일)

## 방법 3: curl로 테스트

Postman 대신 터미널에서 curl 사용.

```bash
# 1. 로그인
curl -c cookies.txt -X POST http://localhost:8080/api/v1/users/login \
  -H "Content-Type: application/json" \
  -d '{"email":"test@test.com","password":"password123"}'

# 2. 주문 생성
curl -b cookies.txt -X POST http://localhost:8080/api/v1/orders \
  -H "Content-Type: application/json" \
  -d '{"addressId":1,"items":[{"productOptionId":1,"quantity":1}]}'

# 3. 결제 승인 (Mock 모드)
curl "http://localhost:8080/api/v1/payments/success?paymentKey=mock_key&orderId=ORD-20260401-a1b2c3d4&amount=129000"

# 4. 주문 확인
curl -b cookies.txt http://localhost:8080/api/v1/orders/1
```

## 위변조 테스트

금액을 조작하여 검증 로직이 동작하는지 확인:

```
GET http://localhost:8080/api/v1/payments/success?paymentKey=mock_key&orderId={pgOrderId}&amount=1000
```

DB에 저장된 금액(예: 129000)과 다른 금액(1000)을 보내면 아래 에러가 반환되어야 정상:

```json
{
  "status": 400,
  "code": "PM002",
  "message": "결제 금액이 일치하지 않습니다"
}
```

## 결제 실패 테스트

```
GET http://localhost:8080/api/v1/payments/fail?code=PAY_PROCESS_CANCELED&message=사용자가 결제를 취소했습니다&orderId={pgOrderId}
```

서버에서 자동으로:
- Payment 상태 → ABORTED
- 주문 취소 + 재고 복구
- Redis 타임아웃 타이머 제거

---

## 에러 발생 시 확인 순서

1. IntelliJ 콘솔 로그 확인 — 토스 에러 메시지가 찍힘
2. application.properties의 시크릿 키가 맞는지 확인
3. 샌드박스에 입력한 amount와 주문 생성 시 받은 finalAmount가 동일한지 확인
4. 토스 결제 세션은 10분 후 만료 — 10분 이내에 진행해야 함
5. pgOrderId가 정확히 일치하는지 확인 (대소문자, 하이픈 포함)
