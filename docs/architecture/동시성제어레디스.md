# 재고 동시성 제어 — 비관적 락에서 Redis DECR로 전환 프롬프트

## 전환 배경
현재 비관적 락(SELECT FOR UPDATE)으로 재고를 차감하고 있다. 동시 1000명이면 마지막 사용자가 약 10초 대기하는 병목이 있다. Redis DECR 원자적 연산으로 전환하여 락 없이 ~1ms로 재고를 선점하고, DB에 최종 반영하는 구조로 변경한다.

## 프로젝트 컨벤션 (모든 단계에 적용)
- 패키지: ccommit.stylehub
- 명시적 개별 import (와일드카드 import 금지)
- Javadoc 헤더 필수 (@author WonJin Bae, @created 날짜, 목적 설명)
- 1줄짜리 주석은 `//` 사용
- DDD: 도메인 간 Service 레이어를 통해 소통
- 대용량 트래픽 기준으로 설계

## 현재 구조
- ProductService.decreaseStockWithLock() — 비관적 락(SELECT FOR UPDATE)으로 재고 차감
- ProductService.increaseStock() — 재고 복구
- ProductOptionRepository.findByIdWithLock() — @Lock(PESSIMISTIC_WRITE) fetch join
- OrderTransactionService에서 productService.decreaseStockWithLock() 호출

---

## 1단계: StockRedisService 생성
Redis 재고 관리 전담 클래스를 생성해줘.
- 패키지: ccommit.stylehub.product.service
- StringRedisTemplate 사용
- 키 형식: "stock:option:{optionId}"

### 메서드
- setStock(Long optionId, int quantity) — Redis에 재고 세팅 (SET)
- decreaseStock(Long optionId, int quantity) — Redis DECRBY로 원자적 차감. 결과 < 0이면 INCRBY로 복구 후 INSUFFICIENT_STOCK 예외
- increaseStock(Long optionId, int quantity) — Redis INCRBY로 재고 복구

## 2단계: ProductOptionRepository 수정
비관적 락 없는 fetch join 조회 메서드를 추가해줘.
- findByIdWithStore(Long optionId) — @Lock 없이 JOIN FETCH po.product p JOIN FETCH p.store
- 기존 findByIdWithLock()은 재고 수정 API에서 계속 사용하므로 유지

## 3단계: ProductService 수정
decreaseStockWithLock()을 decreaseStock()으로 변경해줘.

### decreaseStock(Long optionId, int quantity)
1. stockRedisService.decreaseStock() — Redis에서 재고 선점 (원자적, 락 불필요)
2. productOptionRepository.findByIdWithStore() — DB에서 옵션 조회 (락 없는 fetch join)
3. option.decreaseStock(quantity) — DB 재고 확정

### increaseStock(Long optionId, int quantity)
1. stockRedisService.increaseStock() — Redis 재고 복구
2. productOptionRepository.findById() — DB 옵션 조회
3. option.increaseStock(quantity) — DB 재고 복구

### 상품 등록 시 Redis 재고 세팅
registerProduct()에서 트랜잭션 커밋 후 각 옵션의 재고를 stockRedisService.setStock()으로 Redis에 세팅

### 재고 수정 시 Redis 동기화
updateStock()에서 트랜잭션 커밋 후 stockRedisService.setStock()으로 Redis에 동기화

## 4단계: OrderTransactionService 수정
decreaseStockWithLock() 호출을 decreaseStock()으로 변경해줘.
- deadlock 방지를 위한 mergeAndSort()는 그대로 유지 (Redis에서도 순서대로 차감하는 게 일관성에 좋음)

## 5단계: 동시성 테스트 수정
OrderConcurrencyTest에서 테스트 전 Redis에 재고를 세팅하는 로직 추가해줘.
- stockRedisService.setStock(optionId, 10) 추가
- 테스트 후 Redis 재고도 0인지 검증 추가

## 주의사항
- Redis 세팅은 반드시 트랜잭션 커밋 후에 실행 (롤백 시 Redis에만 세팅되는 문제 방지)
- Redis 장애 시 비관적 락으로 폴백하는 로직은 현재 단계에서 불필요 (추후 검토)
- 기존 테스트 데이터(300만건)의 옵션에 대해 Redis 초기 세팅이 필요할 수 있음
